# NUI v7 — Concrete Craft & Authority Intelligence

## Problem
NUI v6 is strong at meta-intelligence: it knows that typography, motion, accessibility, enterprise workflow, service UX, component semantics, source archaeology, and visual ambition need owners and evidence. The remaining failure mode is **meta-intelligence without enough accumulated concrete design knowledge**. An agent can route correctly yet still spend too long reinventing decisions that mature systems have already validated in production, or it can read a visually impressive source and give it authority outside its competence.

NUI v7 must convert accumulated external practice into a bounded, agent-readable authority mesh and a concrete decision fast path without cloning third-party design systems, copying trade dress, or treating popularity as truth. It must also close the gap between design prose and rendered output by requiring perceptual evidence for claims about craft.

## Goals
1. Route each design decision to the strongest relevant authority, not to one universal UI source.
2. Preserve authority dimensions: platform, service UX, accessibility semantics, enterprise workflow, commerce, AI collaboration, visual craft, motion, implementation, and agent-readable tooling can have different winners.
3. Distill concrete, source-bound pattern cards that accelerate execution while preserving provenance, contraindications, and validation obligations.
4. Add an immediate execution packet so NUI can answer quickly when the task does not need a long committee-style process.
5. Require rendered perceptual evidence for high-ambition claims: hierarchy, typography, material roles, responsive recomposition, motion sequence, signature, and state coverage.
6. Treat MCP/LLM docs/skills/open-code distributions as execution adapters, not as semantic authority by default.
7. Keep third-party content pointer-based where copying would create legal, drift, or attribution risk.

## Non-goals
- Claim objective universal beauty.
- Copy proprietary design-system text or visual trade dress into NUI.
- Replace React Aria/Radix/Motion/Spectrum/Apple HIG/GOV.UK/USWDS/SAP/etc. with prose summaries.
- Make one component library the default for every stack.
- Inflate the skill graph without a unique decision owner.

## Architecture

### Plane A — Decision Authority Mesh
A versioned `ui-authority-mesh-v7.json` models **decision dimensions**, not source prestige. Each source can be authoritative in one dimension and only inspirational in another. The resolver returns primary authority, corroborating authorities, implementation adapters, visual references, conflicts, and live-verification obligations.

### Plane B — Concrete Pattern Knowledge
`concrete-design-patterns-v7.json` stores compact, hand-distilled pattern cards. Every card has a problem, concrete decision, rationale, source references, contraindications, validation evidence, and transfer boundary. Cards are deliberately narrower than general principles.

### Plane C — Immediate Execution Synthesis
A deterministic compiler creates a bounded `concrete-design-packet`: task thesis, authority stack, 5–9 prioritized decisions, implementation shortcuts, perceptual obligations, unresolved questions, and explicit reasons not to invoke heavyweight research. The packet optimizes latency without bypassing safety/platform/semantic authority.

### Plane D — Rendered Perception Loop
A `rendered-perception-evidence` contract requires state/viewport captures and artifact-level observations. Presence of a screenshot is insufficient. High-ambition work must identify focal order, type resolution/fallback, density/material structure, signature mechanism, responsive recomposition, and temporal staging if motion is material. Pixel-diff evidence must include calibrated tolerance rationale so anti-aliasing noise is not mistaken for regressions.

### Plane E — Agent-readable Adapters
`agent-readable-ui-sources-v7.json` records public LLM docs, MCP servers, skill suites, registries, and open-code distributions. These are access mechanisms. They may accelerate retrieval/implementation but do not raise source authority above the underlying design/semantic evidence.

## New decision owners
1. `routing-to-ui-authorities` — owns decision-dimension authority selection.
2. `compiling-concrete-design-packets` — owns bounded immediate execution synthesis.
3. `adapting-institutional-design-knowledge` — owns transfer from accumulated institutional practice into local decisions without authority smear.
4. `orchestrating-implementation-authorities` — owns separation of semantic/behavioral authority, visual inspiration, and implementation accelerator.
5. `validating-rendered-perception` — owns output-level perceptual evidence.
6. `designing-domain-native-signatures` — owns signature mechanisms derived from the subject/domain rather than generic AI aesthetics.
7. `building-agent-readable-ui-context` — owns efficient use of MCP/llms/skills/open-code sources.
8. `compressing-ui-decisions-for-execution` — owns latency-aware compression without dropping hard obligations.

## Authority rules
- Explicit product/safety/law remain above every external system.
- Platform-native work routes platform feeling and native convention to platform authority (for Apple targets, Apple HIG outranks generic NUI aesthetic preference).
- Component interaction semantics route to implementation-tested semantic authorities (e.g. React Aria/Radix) before visual galleries.
- Public-service flows route service patterns and evidence to institutional service systems (e.g. GOV.UK/USWDS where jurisdiction/context fit), while local law/project evidence still wins.
- Enterprise workflow semantics route to systems with real enterprise workflow lineage (e.g. SAP Fiori/Ant/Carbon by fit), not to visual galleries.
- Commerce admin/merchant work may use Shopify sources for Shopify-specific mental models and implementation, but must not generalize Shopify conventions to all commerce.
- Visual frontier sources may inspire signature mechanisms but never become sole semantic or accessibility authority.
- MCP/LLM docs/agent skills are retrieval interfaces; authority derives from the underlying source and evidence, not the protocol.

## Completion gate
V7 completion wraps v6. It blocks when:
- a declared authority-sensitive decision lacks an authority route plan;
- material institutional knowledge is used without provenance/transfer boundary;
- an implementation shortcut is chosen without separating semantics, visual language, and implementation roles;
- high-ambition work lacks rendered perceptual evidence;
- a screenshot is present but state/viewport/typography/signature observations are absent;
- motion is material but no temporal evidence/reduced-motion equivalent exists;
- a pixel-diff claim has no tolerance rationale and renderer/environment identity;
- immediate fast-path output omits hard obligations or unresolved blockers.

## Research principles encoded from 2026 survey
- Mature design systems win through accumulated production lineage, not merely component count.
- Fewer rules can be deeper when they are embodied in platform/hardware/software behavior.
- Service design and accessibility need real usage/testing evidence.
- Headless primitives can carry stronger behavioral authority than visually expressive libraries.
- Domain systems can exceed broad ontologies inside their lived vertical.
- Agent-readable design systems (MCP, llms.txt, skills, open code) are becoming an execution layer NUI should route to rather than duplicate.
- Visual libraries and motion engines should be treated as mechanism reservoirs and implementation accelerators, not universal design authority.
