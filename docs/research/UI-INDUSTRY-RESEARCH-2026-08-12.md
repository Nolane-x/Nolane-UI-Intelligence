# UI Industry Research — 2026-08-12

## Executive summary

This research wave expanded Nolane UI Intelligence (NUI) from a 47-skill general UI/UX cognition and verification system into a 125-skill universal graph spanning mainstream product design, human factors, specialized modalities, emerging intelligent systems, safety-critical environments, accessibility subdomains, AI/agent interaction, design operations, and independent verification.

The objective was not to maximize skill count. A new skill was admitted only when research exposed a decision class that could not be cleanly owned by an existing faculty without mixing different authorities, evidence, failure modes, or release conditions. Topics that could be decomposed into existing skills were recorded as decomposition evidence rather than given another name.

The wave ended in **bounded research saturation as of 2026-08-12**. This means the final adversarial primary-source sweep produced zero material non-decomposable decision owners after earlier sweeps had continued to produce new ones. It does **not** mean the UI field is permanently complete, that all jurisdictional regulation has been reviewed, or that NUI is objectively superior to every other UI system. Those claims are explicitly outside the saturation boundary.

Machine-readable evidence lives in:

- `knowledge/ui-domain-atlas.json`
- `knowledge/ui-domain-atlas-emerging.json`
- `knowledge/ui-domain-atlas-emerging-2.json`
- `knowledge/ui-domain-atlas-emerging-3.json`
- `knowledge/ui-domain-atlas-emerging-4.json`
- `knowledge/source-ledger*.json`
- `knowledge/research-saturation.json`
- `knowledge/final-saturation-evidence.json`
- `knowledge/research-radar.json`

The deterministic validator refuses a saturated claim if the required evidence dimensions are not PASS, the final sweep still discovers a new owner, the decomposition evidence is too weak, or the research boundary lacks explicit reopen conditions.

## 1. Research question

The project began with a deliberately difficult question:

> What does an AI agent need in order to design UI/UX as a disciplined industry-wide practice rather than as a visual frontend-generation trick?

A purely visual answer is insufficient. Real interfaces include product semantics, task flow, information architecture, physical and digital input, time, error recovery, attention, cognition, automation, privacy, accessibility, platform conventions, safety, collaboration, media, localization, design-system evolution, and evidence. Some interfaces are used from a sofa with a remote; some while driving; some by pilots; some through gaze or switch scanning; some are generated by AI; some are the communication system of a non-speaking person.

Therefore the research target was not “all UI styles.” It was a **decision-ownership map of the UI field**: which kind of interface decision exists, which skill owns it, which authority can constrain it, which evidence can support it, which critic can falsify it, and which machine-checkable invariant should block an unsupported release claim.

## 2. Method

### 2.1 Primary-source-first authority

The wave used an authority order rather than flattening every recommendation into one pool:

1. explicit product, safety, and accepted-target constraints;
2. applicable law, regulation, and normative standards;
3. safety/regulatory authority guidance;
4. authoritative platform guidance;
5. project design system and validated product evidence;
6. empirical human-factors/usability evidence;
7. mature design-system guidance;
8. high-quality agent/design heuristics;
9. community heuristics;
10. model aesthetic preference.

Community UI skills were useful for discovering agent failure modes, craft language, progressive disclosure, aesthetic exploration, and critique mechanisms. They were not allowed to override WCAG, platform conventions, safety guidance, or the product contract.

### 2.2 Status preservation

Research documents record whether a source is published, current guidance, draft, committee draft, final draft, under systematic review, or high-drift platform material. A draft does not become a normative rule merely because its direction is useful.

Examples:

- WCAG 2.2 remains a normative W3C Recommendation for current web conformance work in this wave; WCAG 3 is tracked as a draft.
- ISO/FDIS 9241-130 is useful evidence that user assistance is a distinct HCI decision class, but its Final Draft status is preserved.
- ISO/IEC DIS 20071-24 establishes an emerging sign-language presentation domain, but NUI does not claim that the draft is already a published universal requirement.

### 2.3 TDD for skill discovery

A candidate domain was accepted only after a pressure test could demonstrate a real gap. The repeated cycle was:

1. search current primary sources and strong design/agent systems;
2. formulate a candidate decision class;
3. attempt to decompose it into existing owners;
4. if decomposition loses material authority or failure semantics, write a RED contract test;
5. observe the RED failure;
6. implement a deep owner skill, atlas cell, source ledger entry, eval, and hard route;
7. run the full suite and repository validator;
8. repeat the search from a different boundary.

This avoided two common failure modes: stopping research when the catalogue merely *felt* large, and creating a new skill for every industry noun.

### 2.4 Depth gate

New v2 skills are not accepted as empty topical shells. Their tests require substantive content and the following sections:

- `Parent Contract`
- `Decision Model`
- `Evidence`
- `Output Contract`
- `Failure Traps`

Extension skills are also routed deterministically when their profile conditions are present. A deep Markdown document that is never selected by the router does not count as coverage.

## 3. The field model

NUI treats interface work as a multidimensional problem rather than a list of app categories.

### 3.1 Surface/environment axis

The current graph can reason about:

- web applications and public web surfaces;
- mobile applications;
- desktop/windowed workspaces;
- foldable and large-screen interfaces;
- TV/10-foot interfaces;
- wearables and glanceable surfaces;
- automotive interfaces with parked/driving distinctions;
- flight-deck interfaces;
- spatial/XR interfaces;
- game HUDs and menus;
- CLI/TUI interfaces;
- embedded and kiosk systems;
- robotic/teleoperation interfaces;
- ambient/context-aware systems;
- supervisory control-room HMI.

These are not aesthetic templates. Each surface changes geometry, viewing distance, attention, input, interruption, environmental conditions, failure recovery, and sometimes certification authority.

### 3.2 Input/output modality axis

The graph separates:

- keyboard/power-user interaction;
- pointer, touch, and pen;
- accessible drag and drop;
- directional focus for gamepad/remote;
- voice/conversational interaction;
- gaze and hand input;
- haptics/multisensory feedback;
- alternative input such as switches/scanning/head control;
- neuroinput/brain-computer interaction;
- physical controls where surface-specific human-factors evidence is required.

Cross-device action equivalence sits above individual modalities: it preserves operation meaning and consequences while allowing device-native triggers.

### 3.3 Human-factors axis

NUI models:

- cognitive load and attention;
- perception and motor control;
- task analysis;
- use-related error;
- fatigue and sustained operation;
- high-stakes decisions;
- usability research planning;
- evidence quality and validity.

This changes the design question from “what layout looks good?” to “what must a person perceive, remember, decide, and physically do under the actual operating conditions, and what happens when they are wrong?”

### 3.4 AI/intelligent-system axis

The graph distinguishes:

- ordinary non-AI UI;
- assistive AI;
- generative AI;
- agentic/autonomous action;
- multi-agent surfaces;
- generative UI;
- affective/adaptive UI;
- ambient/context-aware intelligence;
- embodied/avatar representation.

AI does not receive one generic “AI UX” rule. Uncertainty/provenance, correction, streaming, autonomy, identity, attribution, reversible action, and generated component/action boundaries are separate obligations.

### 3.5 Risk/trust axis

Specialized owners exist for:

- authentication/passkeys;
- permission and consent;
- privacy-sensitive interfaces;
- medical/safety-critical UI;
- financial transactions;
- commerce checkout;
- aviation flight deck;
- supervisory control and robotics.

Safety, accessibility, security/privacy, and AI agency are hard-gate concerns; a strong visual score cannot compensate for their failure.

### 3.6 Temporal/resilience axis

Time is treated as interface behavior:

- latency and progressive feedback;
- streaming responses;
- realtime updates;
- offline/degraded behavior;
- interruption and notifications;
- long-running work;
- duplicate-action risk;
- reconnect/conflict recovery.

A user pressing a button twice because feedback arrived late is a UI correctness problem, not only a backend performance issue.

### 3.7 Accessibility and communication axis

The general accessibility faculty is augmented by deep specialists for:

- cognitive accessibility;
- low vision/high contrast;
- screen-reader experiences;
- reduced motion/photosensitivity;
- alternative input;
- accessibility settings/profiles;
- accessible media alternatives;
- sign-language presentation;
- AAC communication interfaces.

AAC and sign language are deliberately separate. AAC symbol vocabulary, access method, motor-planning stability, and authored communication are different from a natural sign language with linguistic timing, signing space, signer identity, and interpretation quality.

## 4. Expansion waves

### Wave 0 — broad v2 architecture

The first expansion added the research plane plus deep families for human factors, modalities, platform surfaces, AI/agents, trust/safety, temporal behavior, design operations, accessibility specialists, and independent critics.

This wave established the core rule that **the router is part of intelligence**. A huge catalogue loaded into every context is weaker than a smaller context containing the exact faculties required by the task.

### Extension 1 — robotics, ambient intelligence, BCI, control rooms

A later adversarial sweep found four gaps that did not decompose cleanly:

#### Robotic/teleoperation UI

A robot interface combines remote perception, command authority, latency, physical-world consequences, autonomy transitions, target binding, and safe fallback. Treating it as an agent dashboard loses the physical-system hazard model.

#### Ambient/context-aware UI

Ambient systems may sense, infer, and act without the user opening a visible application. That creates distinct notice, context, consent, interruption, override, and invisible-state problems.

#### Brain-computer interface UX

BCI introduces calibration, signal quality, uncertainty, fatigue, false activation, consent, privacy, and alternative-control obligations that do not fit ordinary pointer/gaze/voice models.

#### Supervisory control-room HMI

Long-duration process supervision couples alarm systems, trend/state perception, control authority, shift handoff, degraded operation, and operator workload. It needs its own system-level owner rather than only “data-dense dashboard” rules.

### Extension 2 — affective UI, avatars, AAC

The next sweep produced three new owners:

#### Affective/adaptive UI

The key distinction is the inference chain:

`signal → feature → inferred state → confidence/freshness → proposed adaptation → adaptation authority`

The skill explicitly prevents an inferred emotional state from silently becoming consequential authority. Consent, privacy, ambiguity, cultural variation, false inference, manual override, and manipulation are first-class concerns.

#### Avatar/embodied representation

An avatar is an identity and agency surface. The design must distinguish represented entity from actual controller, define likeness authority, disclose automation, preserve nonvisual attribution, handle impersonation risk, and maintain identity continuity across surfaces.

#### AAC communication

AAC is not “icons with large buttons.” It owns communicative intent, vocabulary architecture, symbol semantics, motor-planning stability, access method, prediction/authorship boundaries, offline communication, portability, and communication-partner roles.

### Extension 3 — cross-device semantics and specialized accessibility media

Four further gaps were discovered:

#### Cross-device action equivalence

Consistency is defined at the canonical operation level, not by forcing identical gestures. The same `delete`, `back`, `confirm`, or `undo` operation must preserve its semantics and consequence while mapping to platform-native input.

#### Accessibility settings/profiles

The setting surface itself must solve a bootstrap paradox: a user may need an accessibility feature in order to reach the setting that turns it on. The skill owns bootstrap entry, safe preview/revert, persistence scope, cross-device translation, system/app precedence, privacy, and recovery.

#### Accessible media alternatives

Captions, subtitles, transcripts, audio description, spoken on-screen text, and other alternatives carry different information and timing properties. Presence of a caption track is not evidence of useful synchronization or information coverage.

#### Sign-language presentation

Sign language is a natural-language access channel. The UI must preserve signing space, facial grammar visibility, readable scale, timing, signer/interpreter identity, user-selected language, provenance for synthetic signing, and coexistence with captions/source media.

### Extension 4 — flight deck and in-product assistance

The fourth sweep added only two owners, indicating decreasing novelty.

#### Flight-deck interfaces

FAA human-factors/certification guidance exposed an authority boundary that could not be reduced to “control-room UI.” Flight-deck design couples phase of flight, crew roles, automation modes, alerts, physical/digital controls, design-related flightcrew error, degraded conditions, workload, and certification evidence.

The skill explicitly refuses to turn its guidance into a compliance claim; actual certification evidence remains outside the authority of an agent skill.

#### In-product assistance

User assistance extends beyond onboarding. Contextual help, explanation, troubleshooting, examples, task-state preservation, uncertainty, escalation, and support automation have their own lifecycle. The skill begins with a hard question: can the primary UI simply be made clearer? Help must not become a patch over bad interaction semantics.

## 5. Final zero-novelty decomposition sweep

The last sweep deliberately searched for new standards and environments likely to break the taxonomy. It produced **zero new non-decomposable owners**.

The important evidence is not “we found nothing.” It is that the findings mapped cleanly into existing faculties:

| Research boundary | Existing ownership |
|---|---|
| ISO 9241-112:2025 information presentation | visual hierarchy, typography, haptics/multisensory, accessibility |
| ISO 9241-222:2026 HCD self-assessment | usability research, evidence validity, design governance, decision documentation |
| ISO/IEC 4944:2024 usability evaluation of natural user interfaces | usability evidence, perception/motor control, research-validity critic |
| ISO/CD 9241-812 intelligent systems | human-AI, agent autonomy, robotics, ambient systems, affective UI, multi-agent surfaces |
| ISO/IEC 7818:2025 voice UI for personal mobility | voice UI, automotive, cross-device action equivalence |
| ISO 9241-920:2024 tactile/haptic interactions | haptics/multisensory, perception/motor, alternative input |
| ISO/IEC 23090-28:2026 immersive media | spatial/XR, accessible media alternatives, haptics |
| IEC 80601-2-78 rehabilitation robotics | medical safety, robotics, accessibility, haptics, safety critic |
| ISO/IEC CD 25420 multimodal customer service | voice, direct input, cross-device action, realtime behavior |
| current Apple generative-AI guidance | human-AI, correction, uncertainty/provenance, AI-agency critique |

This is the central saturation signal: the last search still generated useful **knowledge**, but no longer required a new **decision owner**.

## 6. What the research changed in the router

The v1 router classified product/UI work primarily by intent, surface, information, interaction, visual freedom, constraints, and evidence capability. v2 expands that into a task profile with explicit dimensions for:

- platform surfaces;
- input modalities;
- AI role;
- risk class;
- temporal behavior;
- social context;
- specialized decision domains;
- regulatory/standard sensitivity;
- research freshness;
- environment and error cost;
- available validation capabilities.

The router is **extension-aware** rather than count-aware. It does not contain a rule such as “load 125 skills.” It computes a minimum sufficient graph and then compares it with deterministic hard routes. New research extensions can add route predicates without turning the root router into an encyclopedia.

Examples:

- automotive while driving forces automotive + human factors + safety critic;
- flight deck forces flight-deck + human factors + high-stakes decisions + safety critic;
- spatial/XR forces spatial interface + gaze/hand + platform/modality verification;
- agentic AI forces autonomy + provenance + AI-agency critique;
- affective UI forces affective owner + consent/privacy + security/privacy critique;
- AAC forces root accessibility + AAC owner + applicable real input modality;
- sign-language presentation inherits accessible-media obligations plus its linguistic presentation owner;
- in-product assistance forces UX critique and may still conclude that the underlying UI should be redesigned instead of helped.

## 7. Verification architecture

The research reinforced the separation between generation and certification.

### Generation faculties

They produce product, interaction, visual, platform, accessibility, safety, AI, and specialist contracts.

### Independent critics

Critics own failure discovery and use `may_modify: false`. Current independent courts include visual design, UX, accessibility, design system, responsive behavior, platform fit, human factors/safety, AI trust/agency, input modality, cognitive load, security/privacy, research validity, performance/resilience, and localization.

### Deterministic validators

The Python kernel checks things that should not depend on persuasive model prose:

- graph completeness and parent cycles;
- skill metadata and depth contracts;
- token/state invariants;
- atlas ownership and verifier coverage;
- source authority and freshness;
- mandatory routing;
- evidence-bound completion packets;
- bounded research saturation.

`validate_bounded_saturation` specifically prevents a future maintainer from changing the word `OPEN` to `SATURATED` without final zero-novelty evidence and reopen conditions.

## 8. The meaning of bounded saturation

`SATURATED` is intentionally narrow.

It means:

- the wave was searched repeatedly from independent boundaries;
- early sweeps continued to produce new decision owners;
- the number of new owners decreased across later sweeps;
- the final primary-source sweep produced zero new non-decomposable owners;
- all five dimensions — breadth, depth, contradiction handling, novelty, and freshness — carry explicit PASS evidence;
- machine validators can reject a forged saturation claim;
- the system declares conditions that force research to reopen.

It does **not** mean:

- no future UI field can appear;
- every country’s law or regulator has been reviewed;
- every proprietary platform requirement is included;
- every certification standard has been ingested;
- all research papers have been read;
- NUI is provably better than every design skill or human designer;
- an agent using NUI will automatically produce a beautiful interface without task-specific evidence and iteration.

This distinction is essential. A permanent-completeness claim would contradict the research architecture itself.

## 9. Research radar and perpetual evolution

The user’s requirement that research should continue indefinitely is represented as a **reopenable research system**, not an impossible claim that one session can continue forever.

`knowledge/research-radar.json` watches high-drift areas such as:

- WCAG 3;
- WAI-Adapt/AAC symbol work;
- sign-language presentation standards;
- affective-computing drafts;
- intelligent-system HCI drafts;
- BCI standards;
- rehabilitation-robot safety revisions;
- generative-AI platform guidance;
- visionOS/spatial interaction;
- Material/platform design-system changes;
- Android automotive restrictions;
- A2UI/generative UI;
- FDA human-factors guidance;
- FAA flight-deck guidance;
- Core Web Vitals.

A trigger does not merely update a bibliography. It reopens the affected domain and asks whether the new evidence:

1. changes an existing skill’s decision model;
2. changes authority or release obligations;
3. invalidates an assumption;
4. creates a genuinely new decision owner;
5. requires a new critic or deterministic invariant.

This is how NUI can evolve without turning into an ever-growing pile of duplicated topical skills.

## 10. Source and licensing posture

NUI does not bulk-copy third-party UI skills, proprietary design databases, or paywalled standards.

For external skill systems, NUI studies mechanisms such as routing, visual-target discipline, critique, progressive disclosure, design-system reasoning, and anti-generic heuristics, then independently authors its own contracts.

For standards that are paywalled, only publicly available metadata, abstracts, status, and clearly exposed scope are used unless a licensed copy is explicitly supplied. The repository records this limitation. A source being authoritative does not grant a license to reproduce its text.

Community systems with restrictive licenses are treated especially carefully. For example, NUI did not import the UI/UX Pro Max databases; it only learned from the abstract idea that structured design knowledge can be retrieved contextually.

## 11. Remaining research boundaries

Even at bounded saturation, future high-value research remains expected in these categories:

- new UI and accessibility standards moving from draft to published status;
- jurisdiction-specific digital accessibility or safety regulation;
- platform releases changing native interaction conventions;
- AI agents gaining new action/permission/embodiment capabilities;
- generative UI protocols and safe action-binding models;
- BCI and novel sensor modalities;
- new XR/immersive display and input hardware;
- automotive/aviation/medical certification updates;
- empirical work that falsifies a current human-factors heuristic;
- comparative UI-agent benchmarks showing weaknesses in NUI routing or skill compliance.

The correct response to such evidence is not to defend the current graph. It is to reopen research, run a pressure test, and change the graph if the evidence wins.

---

## Conclusion

The most important result of this wave is not the number **125**. It is the transition from a broad UI design skill set into a **research-governed, evidence-gated, multi-domain UI cognition system**.

NUI now has a mechanism for answering four questions that ordinary UI prompts usually blur together:

1. **What decisions exist in this interface?** — the atlas and router.
2. **Who owns each decision?** — narrow depth-locked skills.
3. **What can prove or falsify the decision?** — authority, evidence, critics, runtime checks.
4. **When are we allowed to say we are done?** — completion and bounded-saturation gates.

That architecture is designed to continue evolving. The current wave is closed because the final adversarial search stopped producing new owners, not because the field has stopped moving.
