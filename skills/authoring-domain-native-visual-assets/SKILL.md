# Authoring Domain-Native Visual Assets

## Parent Contract
**Required parent:** `designing-domain-native-signatures`.

`designing-domain-native-signatures` establishes a product-specific signature from subject-world truth. This owner converts that signature into a production-grade custom visual asset brief while enforcing accuracy and trade-dress distance.

## Decision Boundary
Own the creative brief and truth constraints for new imagery/illustration/3D/data-art. The image tool executes; this owner decides what the asset must mean. Output `domain-native-asset-brief`.

## Subject Grammar
Build a **subject morphology inventory**: forms, materials, processes, tools, environments, scales, textures, symbols and transformations genuinely present in the domain. Convert it into a **domain-material grammar** rather than reaching for generic neon gradients, floating glass spheres or pseudo-scientific grids. Specify **asset truth constraints**—facts that must remain accurate, quantities that cannot be fabricated, labels/geometry that must correspond to real data, and ambiguity that should remain visible.

Establish **trade-dress distance**. References can teach composition, lighting, material treatment or narrative mechanics, but do not request imitation of a living artist, protected character, brand campaign, proprietary interface or recognizable trade dress. Describe visual mechanisms in independent language.

## Brief Anatomy
State semantic job, audience/context, focal subject, narrative moment, camera/viewpoint, depth/material/lighting logic, color relationship to UI, negative space for layout, crop-safe zones, accessibility alternative, responsive variants, delivery format, performance budget, prohibited motifs, provenance requirements and acceptance tests. When generation is probabilistic, include a **custom-media failure brief** listing plausible hallucinations and what to inspect.

## Tool Independence
Do not encode the brief around one generator’s prompt syntax. A good brief can be executed in GPT Image, Blender, Figma/vector tools, photography, 3D or manual illustration. Let `orchestrating-creative-toolchains` choose the tool chain after the asset semantics are stable.

## Decision Model
Inventory morphology/material/process → select semantic moment → bind truth constraints → define composition/negative space/crop variants → set prohibited generic motifs/trade-dress boundaries → define tool-neutral acceptance tests.

## Evidence
Require subject morphology, domain vocabulary, truth constraints, reference-mechanism notes, trade-dress distance, camera/view/light/material logic, crop-safe zones, responsive variants, accessibility equivalent and failure checklist.

## Output Contract
Emit `domain-native-asset-brief` with semantic job, subject grammar, truth/prohibition constraints, composition/material/lighting plan, responsive/crop requirements, provenance rules, tool-neutral delivery spec and acceptance tests.

## Failure Traps
Generic futuristic orb; invented science labels; copied campaign composition; prompt tied to one generator; gorgeous standalone image has no layout-safe negative space; generated hands/product geometry are wrong.

## Falsification
Swap the product domain while preserving the brief. If nearly everything still fits, the asset is generic. Remove the source-world vocabulary and compare; if nothing important changes, domain grounding is insufficient. Inspect generated scientific/technical elements for fabricated meaning.

## Recovery
Discard seductive but untruthful output, return to the morphology inventory/truth constraints, narrow the creative brief, choose a more controllable tool or real source media, then validate the asset only inside the final UI context.
